# Product

## Register

product

## Users

The primary user is the owner operating native OpenClaw Main as the everyday Project Northstar work surface. They move between normal assistant conversation, durable project conversations, sessions, agents, plans, implementation evidence, and approvals without manually rebuilding context in a terminal or leaving the main application for a separate dashboard.

## Product Purpose

OpenClaw Main is a calm, authoritative workspace for assistant use and supervised project work. The center conversation remains the primary interaction and decision surface. Navigation and contextual detail support that conversation by making projects, sessions, active work, provenance, and evidence understandable without competing with it. Success means the owner can resume work, understand current state, converse, supervise, and act with confidence from one native workspace while ordinary chat remains simple.

## Brand Personality

Calm, precise, capable. Project Northstar carries the recognizable Glass OS identity through dark luminous atmosphere, warm foregrounds, exact hierarchy, and restrained material depth. Glass is a rare structural cue for hierarchy and focus, never decoration applied to every object.

## Anti-references

- Generic public SaaS dashboards or AI control centers designed for broad marketing appeal.
- Card walls, nested cards, excessive pills, capsule-shaped navigation everywhere, or rounded geometry that clips text and borders.
- Broad wildcard styling such as `[class*="nav-"]` or `[class*="sidebar"]` that leaks across unrelated components.
- Gradient text, decorative blur, default glassmorphism, noisy neon, ambient effects that compete with content, and motion without state meaning.
- A detached project dashboard, plugin-only primary workspace, or inspector that displaces the authoritative Main chat.

## Design Principles

1. **Conversation is authority.** Keep Main chat central and make supporting state point back to it.
2. **Owner comprehension comes first.** Show identity, current context, state, provenance, and next action without exposing raw runtime clutter.
3. **Hierarchy earns material.** Use Glass OS depth only where it clarifies shell, focus, ownership, or transition.
4. **Native before novel.** Extend existing OpenClaw navigation, chat, routing, and interaction patterns instead of building a parallel product.
5. **Calm under load.** Dense project activity remains legible, stable, and progressively disclosed rather than becoming a wall of badges and cards.

## Accessibility & Inclusion

The workspace must remain complete with reduced motion and reduced transparency, and it must preserve semantics, borders, focus, selection, and status in forced-colors mode. All navigation, chat, inspector, drawer, and disclosure actions must work by keyboard with a clear visible focus indicator and predictable focus return. Layouts must remain usable at 200% text zoom, at compact widths, and with long labels without clipping, overlap, hidden primary actions, or horizontal page scrolling. Color, blur, depth, and motion never carry meaning alone.
